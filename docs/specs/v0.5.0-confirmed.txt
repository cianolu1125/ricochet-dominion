一、文档定位与执行优先级

1. 本文是本次 v0.5.0 更新的完整执行规格，已整合原始 v0.5.0 文档、对 v0.4.0 的审查结论，以及用户对 18 项问题的最终答复。
2. 以现有 v0.4.x 正式项目为基础增量开发。本文明确修改的规则采用新定义；本文明确保留及未涉及的规则沿用现版实现。开发时先读取现版规则内核、测试、配置与正式发布版本，建立基线。
3. 冲突处理优先级：本确认版 > 之前的 v0.5.0 草稿与审查建议 > v0.4.x 的对应旧规则。旧测试中与新规则冲突的预期随规格更新。
4. 本文件是更新规格，不是重新设计全部底层物理。地图尺寸、初始 HP、移动距离、速度衰减、飞弹终止条件、建塔资格、手动拆塔资格、稳定据点网络定义、旧伤害触发条件等未改数值从现版读取，保持原值；完成基线表并纳入开发记录。
5. 规则计算产生真实状态，反馈系统表现已经成立的规则事件。视觉动画不决定领地、HP、Charge 或胜负。
6. 本次用户请求的交付物是本文 TXT。后续开发、提交与发布属于下一阶段；本文第十九部分给出该阶段的验收与交付要求。
7. 本文中的时间、尺寸和透明度是明确默认实现参数。允许在实机验证中做小幅视觉调优，并记录最终值；玩法门槛、结算顺序、触发条件保持固定。

二、版本目标与变更边界

2.1 最终目标
保持双人热座弹射游戏的轻量、流畅与直接操作感，让零塔、一塔、三塔、五塔分别拥有猎杀、扩张、切割、攻城的战略路径。平时画面干净，关键瞬间集中发光与爆发；连续真实事件保留打击感，同次衍生反馈统一调度。

2.2 保留的现有能力
• 本地 PVP 热座，两人共用设备。
• 每个 Turn 的“移动”和“行动”自由先后；各自使用次数与消耗规则沿用现版。
• 先锋移动、飞弹首次发射、据点捕获后的重新弹射，均通过拖拽操作。
• 中继仍然是“己方据点实体捕获飞弹 → 玩家重新瞄准 → 从该据点重新弹射发射”，保留现有暂停等待输入与重新发射机制。
• 先锋移动中的据点中继沿用现版，独立于飞弹蓄能。
• 手机竖向战场：当前方下方，对方上方，切 Turn 旋转战场 180°；桌面横向战场：红左蓝右固定。
• 短箭头、方向提示、极近距离提示；远处继续使用现版有限辅助，不增加全路径精确预测。
• 红蓝归属、四连通、Stable / Temporary、现有成长阶段、五塔上限、Feedback Director、现版主题与设置。
• 己方静止先锋与己方据点重合时的碰撞豁免沿用现版；真实运动碰撞沿用现版。
• Tutorial 与 Computer 保持 Coming Soon。

2.3 修改的玩法
• Charge 由实际不同据点捕获数按 1 / 3 / 5 升级。
• Charge 0 同样具备现有的敌方先锋捕获与携带能力。
• Charge I 最终 5×5 染色；Charge II 为 3×3 + 全图十字；Charge III 为 5×5 + 全图十字 + 实体攻城。
• Pending Capture 从固定目标快照改为动态同色 Temporary 连通块争夺。
• 到达轮数上限后仍同分，按现版非平分胜负判据完成比较后宣布平局，不进入加时。

2.4 明确并完善的已有规则
• 据点最多五座，包含出生据点；满额保留重新部署。
• 成长重新检查完整几何范围，所有实际改色只发生在未被敌方保护的格子。
• 保护状态支持多个己方据点覆盖同一格，删塔后重算仍存活来源。
• 同一枚飞弹的同塔一次捕获记录使用稳定唯一 ID。
• HP 归零立即结束，优先于尚未发生的攻城与最终染色。

2.5 新增 UI 与修复
• 随当前己方据点数展示 0–5 节点的顶部蓄能轨。
• Charge I / II / III 的无框技能名称。
• 先锋附近的移动／行动菜单及行动竖列。
• 地图状态层级、十字传播、已中继塔标记、关键 Hit Stop。
• Custom 1–100 轮与三位数布局。
• 返回主菜单状态清理、第二局稳定性、移动端音频恢复。

三、基础术语与单一规则来源

3.1 术语
先锋：玩家操控的圆形角色。
据点：方形塔实体，拥有唯一 ID、阵营、成长阶段和保护覆盖。
Turn：一方的单次回合。
Round：沿用现版红蓝双方完成 Turn 的整轮定义。
中继：据点捕获运动中的己方飞弹，暂停运动并允许玩家重新弹射。
Relay Count：当前这一枚飞弹实际被不同己方据点有效捕获的累计次数。
Charge：由 Relay Count 推导的能力等级。
Protected：某格当前受到存活有效据点保护，保持其所属阵营颜色。
Pending Capture：Temporary 区域正在被另一阵营争夺，等待约定到期时点结算。

3.2 中继计数与塔数的区别
据点总数是当前战场资源；Relay Count 是本枚飞弹的历史捕获进度。
拥有五座塔而只中继两座，等级仍为 Charge I。
顶部显示节点数由当前己方塔数决定；点亮数由当前飞弹中继数决定。
在正常现版回合结构中，飞弹链期间不能另行建塔、拆塔或重新部署，塔数与历史进度不会因这些行动在链中矛盾变化。

3.3 统一函数
MAX_TOWERS = 5。
relayCount = visitedRelayTowerIds.size。
chargeFromRelayCount(0) = 0。
chargeFromRelayCount(1 或 2) = I。
chargeFromRelayCount(3 或 4) = II。
chargeFromRelayCount(5) = III。
规则内核、菜单、飞弹外观、HUD 和说明共用同一个等级函数与同一份能力配置。

四、据点数量、建立与重新部署

4.1 数量
每方最多五座存活据点，出生据点计入数量。数量从真实存活集合计算。
少于五座时，行动入口为“建立据点 / Build Outpost”。
达到五座时，入口为“重新部署据点 / Redeploy Outpost”。
菜单可附小型 5/5 数量文本，按钮主名称保持上述文字。
零塔是合法状态，先锋仍可按现版资格重新建塔、发射基础飞弹和战斗。

4.2 重新部署流程
玩家选择该入口 → 进入旧塔选择状态 → 选择允许移除的己方塔 → 校验先锋当前建塔位置 → 一次原子操作移除旧塔并建立新塔。
出生据点的可选择资格沿用现版，所有旧塔选择与建塔位置合法性规则保持现版。
整次成功重新部署消耗一次行动；中途取消、位置不合法或旧塔失效时不消耗。
新塔从 1×1 开始，使用新 ID 和新成长计时；同坐标也视为新实体。
成功提交后仍为五塔，不产生可操作的“先少一塔再多一塔”中间状态。
移除旧塔解除该塔保护贡献，旧位置领地颜色保留；其他塔仍覆盖的格子继续保护。
新塔染色与保护按现有建立规则处理，地图状态与动态争夺随后统一更新。

4.3 行动互斥
飞弹飞行、捕获等待重新发射、先锋运动和结算过程中，根据现版状态机仅开放对应合法操作。重新部署不能插入一枚飞弹的中继链。

五、成长染色与保护覆盖

5.1 成长阶段与时序
继续采用 1×1 → 3×3 → 5×5，成长触发回合与年龄规则沿用现版。
建立时的 1×1 行为沿用现版；成长时本版明确完整范围复查。
成长几何范围以塔中心格为中心，地图外部分裁剪到实际地图内。

5.2 完整范围复查
1×1 升到 3×3：检查完整 3×3。
3×3 升到 5×5：检查完整 5×5，包括此前内圈因敌方保护而没取得的格子。
允许中立、己方、未受敌方保护的敌方 Stable 或 Temporary 格变为成长方颜色。
敌方 Protected 格保持原色和原保护归属。
已属己方且已经受保护的格子不重复播放夺取／成长改色动画。
5×5 达到满级后保持阶段，不在每帧或每个后续回合持续补染；后续改色依赖明确规则事件。
成长的局部改色与稳定状态更新可以扩展／解除既有争夺，但不会凭空执行整块吞并。

5.3 保护数据的定义
保护由存活有效据点、其成长范围、该格阵营归属和既有保护优先规则共同计算。
同方覆盖：一个格可以拥有多个保护来源，使用 Set<towerId> 或等效可重算数据。
保护条件：该格属于阵营 P，且至少一座有效 P 据点当前的有效保护覆盖包含它。
敌方已保护格优先保留，后成长的异方塔几何范围经过该格时不会取得其颜色或保护。
因此“位于几何方框内”只是候选范围；敌方已保护格不自动变成双方共同 Protected。
同阵营的有效范围重叠正常建立多个来源，不受单个塔索引限制。

5.4 移除塔后的计算
先移除实际塔实体，再按全部剩余塔重算保护贡献及地图状态。
例如 A、B 同时保护格 X，移除 A 后 B 仍有效覆盖 X，则 X 继续 Protected。
若 X 的所有有效来源均消失，X 解除 Protected，但颜色保持；其 Stable / Temporary 再按网络判定。
保护来源可随改色、成长、建立、拆除与重新部署重新计算；UI 不保留失效保护描边。

5.5 成长批次顺序
新 Turn：检查地图 → 到期争夺结算 → 当前方据点成长 → 更新保护、连接和争夺。
同方同时成长使用稳定顺序（沿用现版确定顺序；若现版无显式顺序，则按建立序号升序，再按 ID 排序），计算过程不依赖渲染数组。
预先计算本批次合法目标，统一提交并统一刷新状态。两个己方塔对同一格只产生一次改色视觉，保护来源都保留。

六、Stable、Temporary 与动态争夺

6.1 色彩与连接
Stable 满足现版正式据点网络稳定条件。
Temporary 失去有效稳定连接，仍保留原阵营颜色。
区域识别使用“同色 + 四连通”；斜角接触不相连，异色相邻不合并。
Pending Capture 是 Temporary 上的争夺状态，不是第三种无色领土。

6.2 争夺触发
按现版合法条件，在敌方 Temporary 区域建立入侵据点时创建争夺。
建立造成的局部中心改色按现版规则执行；对原敌方剩余 Temporary 区域建立争夺关联。
争夺到期沿用现版窗口：在发起方下一次己方 Turn 开始时，成长前结算。
拆塔造成断联本身只改变 Stable / Temporary；已有异方塔仅因“剩下它一个”不会触发整区即时翻色。新争夺仍要求符合建立事件触发条件。

6.3 用户最终确认：动态整个连通块
争夺的目标是当前仍同色、仍 Temporary 的整个四连通块。
对方为正在争夺的区域连接新的同色 Temporary 格时，新格在该次地图更新完成后马上进入同一争夺状态，使用原到期时间。
新格无需另等一轮，结算时纳入整个当前连通块。
对方新领土如果只是异色相邻或斜角相接，则不加入。
争夺计时不因扩展、分裂、合并而重新开始。

6.4 如何追踪动态区域
使用区域关联记录与地图重算，保留来源据点、发起阵营、原属阵营、到期 Turn 和当前区域种子／成员定位。
种子／历史成员用于找到争夺区域的延续关系，不是吞并面积上限。
每次地图改变后：
A. 按现版稳定规则重新识别同色 Temporary 连通块。
B. 找到与上一状态仍存续的争夺成员有交集的当前同色 Temporary 连通块。
C. 把这些完整当前连通块关联到该争夺记录，包含新连接的合法 Temporary 格。
D. 更新当前区域成员，解除已改色、已稳定或已脱离继承关系的状态。
E. 清理失效来源与空记录，提交最新 Pending 状态。
一次地图事务内使用事务前成员与事务后完整区域计算延续关系，避免先清掉成员再查询导致记录丢失。

6.5 分裂
争夺块被切成多个同色 Temporary 子块时，每个保留原争夺成员的子块继承原来源集合和到期时间。
某个子块恢复 Stable 后解除争夺，其余仍 Temporary 子块继续。
这一处理把切割视为同一争夺区域的拓扑变化，不额外增加“来源塔必须贴着每个碎块”的新限制。
完全没有延续成员的新独立区域不会自动继承远处争夺。

6.6 恢复稳定与重新断联
区域恢复原属阵营稳定连接后，当前对应块立即解除 Pending 状态，不再在本次到期吞并。
之后再次断联不会凭旧历史自动恢复已取消争夺；需要新的合法争夺触发，或与仍有效的 Pending Temporary 块重新四连通后加入。

6.7 来源据点消失
每条争夺关联记录维护其合法来源塔集合。
来源拆除或重新部署后移除旧 ID 的贡献；同位置新塔不会自动继承旧来源资格。
某争夺关联的全部来源消失时，该关联立即取消。
区域还受其他有效争夺记录影响时，继续显示剩余记录。

6.8 区域合并与多来源
同色 Temporary 块连入有效争夺块后，整块加入争夺。
多个同一争夺方的记录合并到同一连通块时，保留各自存活来源和到期时间；结算采用其中最早到期的有效记录。
更早记录的来源全部失效时，该记录取消，使用仍有效记录的最早到期时间。
一个格的颜色只有一个原属阵营，红蓝两方游戏中其有效争夺方只能是另一方；不引入第三方竞争机制。

6.9 到期结算
在到期方 Turn 开始时，先根据最新地图重新寻找受有效到期记录关联的整个同色 Temporary 连通块。
对这些完整区域批量翻为争夺方颜色；仍受敌方保护的格子保持原色。
Protected 正常应由稳定网络保证其合法状态；保留此逐格保护校验作为统一局部保护规则。
同一格重复命中多个记录只处理一次，吞并后刷新保护、Stable / Temporary、剩余争夺。
结算成功后使用领土吞并反馈，不为每格播放声音。

6.10 示例
红 Temporary 的 A 块正在被蓝方争夺，蓝方下一 Turn 开始到期。
红方在该 Turn 将红 Temporary 的 B 块通过同色四连通桥接入 A。
地图事务结束后 A+B 均为蓝方 Pending；到期时若仍断联且来源有效，蓝方取得整个当前 A+B。
若红方恢复 A+B 的稳定连接，争夺解除；若桥被切断，仍具继承成员的子块按 6.5 分裂规则处理。

七、飞弹生命周期与中继机制

7.1 生命周期
首次发射创建一枚逻辑飞弹，Charge 0、relayCount 0、visitedRelayTowerIds 为空。
飞行、据点捕获暂停、重新瞄准、重新发射和后续捕获均属于同一枚逻辑飞弹。
只有最终完成染色、主动结束该链、HP 终局或退出对局，才结束生命周期并清除本枚记录。

7.2 发射源
从先锋脚下己塔首次发射不自动中继，不自动增加 Charge。
起飞时沿用现版发射源临时碰撞豁免；完全离开实体后解除。
离开后真正撞回这个尚未使用的源塔，触发首次捕获并计数。
中继塔重新发射同样具有离开前短暂源碰撞豁免；离开后再次撞回已用塔按反弹处理。

7.3 有效捕获
飞弹实体碰撞存活己方塔实体，且 ID 尚未使用：
暂停飞弹物理运动 → 位置捕获到塔 → 写入 ID → 推导 Relay Count 与 Charge → 生成对应反馈 → 进入现版重新拖拽发射状态。
出生塔与普通己塔均可以参与。
飞弹穿过保护区但未触碰实体时不捕获。
一次捕获只记一次，实体连续接触的多帧不重复触发。
聚能中心是实际捕获飞弹的据点中心。

7.4 已用塔
同一飞弹再次撞到已记录 ID：沿用实体碰撞法线与反弹物理；飞弹继续运动；播放真实反弹火花与音效，塔上已用标记短闪。
该碰撞不暂停等待重新发射、不增加进度、不重播升级聚能。
碰撞接触进入／离开沿用现版去重方式；连续不同真实碰撞仍分别发生。
例：A 捕获 → B 捕获 → A 反弹 → C 捕获，Relay 为 3，Charge II。

7.5 捕获后的输入
反馈播放过程中尽快进入可瞄准状态，采用现版输入节奏，不强迫玩家等完整装饰尾光。
取消瞄准：停留在当前捕获塔，保留该链所有使用记录、等级、携带状态与合法重发资格。
结束回合：按现版合法入口结束飞弹链，在当前捕获中心执行对应等级最终染色与十字，然后完成交接。
携带角色如何跟随据点捕获／重发沿用现版绑定方式；正式释放时采用第九部分的染色前伤害顺序。

7.6 先锋移动中继
继续现版机制与对应反馈，使用其自身状态记录。先锋移动不会改写飞弹 visited 集合、Charge 或顶部中继进度。

八、Charge 完整能力表

8.1 Charge 0
有效不同据点捕获：0。
最终中心染色：3×3。
敌方先锋捕获／携带：具备。
十字：无。攻城：无。
战略：零塔仍可追击角色与正常局部染色。

8.2 Charge I
有效捕获：1–2。
最终中心染色：5×5。
继承捕获／携带。十字：无。攻城：无。
技能名称：Charge Ⅰ · 扩张。
英文：Charge Ⅰ · Expansion。

8.3 Charge II
有效捕获：3–4。
最终中心染色：3×3。
十字：最终中心所在完整行与完整列，均为一格宽，到实际地图边界。
继承捕获／携带。攻城：无。
技能名称：Charge Ⅱ · 切割。
英文：Charge Ⅱ · Crosscut。

8.4 Charge III
有效捕获：5。
最终中心染色：5×5。
十字与 Charge II 相同。
实体直接撞敌方塔时具备现版攻城摧毁能力。
继承捕获／携带。
技能名称：Charge Ⅲ · 清洗。
英文：Charge Ⅲ · Purge。
“清洗／Purge”是名称，其规则效果精确为 5×5 + 十字 + 直接实体攻城，面积按本节计算。

8.5 升级依据
塔数提供可用中继资源，等级始终来自本枚飞弹实际已捕获的不同塔数。
第 2、第 4 次增加进度而不升级。
等级没有永久科技解锁。下一枚飞弹重新从 0 开始。
有效链内保留已获得等级，按历史记录推导；不根据 UI 可见节点数反算。

8.6 手感统一
所有等级使用相同拖拽灵敏度、发射力度曲线、箭头长度规则、方向显示、近距提示与物理参数。
等级只改上述战略能力与视觉声音表现。

九、碰撞、携带、攻城、染色与胜负顺序

9.1 连续真实事件
每次实际碰撞、每次按现版条件成立的 HP 扣减产生独立事件 ID。
角色碰撞与携带过程继续使用现版伤害条件和去重逻辑，基础弹新增进入同一捕获／携带分支。
本次调整能力门槛与释放顺序，不扩展额外伤害类型。

9.2 HP 最高优先级
任何合法 HP 扣减后立即检查归零。
归零：确定胜者 → 终止剩余物理／行动／未提交地图效果 → 清理本枚飞弹 → 播放已发生伤害及中性终局反馈。
尚未发生的攻城、中心改色、十字和争夺副作用不继续执行。
已有规则状态提交保持，不倒回已发生事件。

9.3 先锋与塔重合
Ⅲ级飞弹轨迹真正命中敌先锋实体：先处理角色命中、携带／伤害与 HP。
若 HP 未归零，继续处理同处塔的直接实体攻城碰撞。
若只擦到塔体而不碰到先锋，则按塔体直接攻城。
判断用实际实体几何碰撞，渲染层重合不等于命中两个目标。

9.4 攻城
Charge III 飞弹实体直接碰撞敌塔时执行现版摧毁。
移除塔，更新其保护贡献；其他己方塔重叠保护保持。
十字线经过塔不构成实体攻城，不摧塔、不伤塔。
攻击结束位置、飞弹终止方式沿用现版直接攻城路径；最终涂色能力改用本版配置。
拆塔和最终地图提交尽可能按现版可复用规则事务处理；需要先解除被摧塔保护，再计算最终合法染色目标。

9.5 最终释放伤害
飞弹最终停止或主动结束链时，先确定合法停止中心和角色释放位置。
以最终染色之前的地图，按现版伤害条件结算携带角色释放。
未结束对局再执行中心／十字染色。
普通结束、据点结束和攻城结束统一该顺序，避免同一落点因路径不同而出现伤害差异。
最终染色与十字本身不造成范围 HP 伤害；脚下因这次改色变成己方颜色也不额外触发 HP 扣减。

9.6 中心与十字计算
中心格沿用现版连续坐标转格和边界裁剪函数。行列在逻辑地图坐标计算，随战场渲染旋转。
计算 centerArea；按等级计算 row、column；并集去重，中心行列交叉只处理一次。
对目标格使用移除被摧塔后、最终改色前的保护状态校验。
敌方 Protected 保持原色；其后方合法格继续改色。
允许格统一提交为飞弹所属阵营色，随后统一重算保护、稳定和动态争夺。
地图外范围裁剪，不绕地图，不逐格刷新连通。
动画从中心传播，逻辑改色一次提交，动画进度不暴露半完成地图供规则判胜。

9.7 普通完整结束顺序
物理停止／主动结束 → 取得中心与释放位置 → 释放伤害与即时 HP 检查 → 必要塔移除后的保护更新 → 生成中心和十字并集 → 合法格批量改色 → 重算 Stable / Temporary 和动态 Pending → 生成反馈 → 同步 UI → 按现版 Turn 完成逻辑交接。
直接实体攻城先处理第 9.3 的角色优先及对应 HP 检查，再移除塔；后续最终释放仍遵守 9.5。
角色已因同一触发结算伤害时，沿用现版事件去重，不为了统一顺序重复扣一次。

9.8 胜负与平局
HP 归零立即胜负。
现版 80% 领地胜利继续在整 Round 结束的既定位置检查；阈值和统计口径保留。
Round Limit 达到时按现版终局比较指标及先后顺序判断胜者，指标仍完全同分则平局。
本版不进入加时，轮数最大为玩家选择的 Round Limit。
Custom 只修改轮数上限，不修改其他即时或整轮胜利条件。
一旦 match 已终结，所有后续命令与旧回调不能改变胜负。

十、顶部中继轨与无框技能名称

10.1 显示节点数
N = 当前行动方存活己方据点数，范围 0–5，包含出生塔。
N=0：轨与节点隐藏；基础弹的发射／携带反馈照常存在。
N=1：只显示第 1 节点。
N=2：显示第 1、2 节点。
N=3：显示第 1、2、3 节点。
N=4：显示第 1–4 节点。
N=5：显示完整第 1–5 节点。
节点代表捕获进度序号，不代表某一座具体塔的身份；具体已使用塔在地图上单独标记。
缺少的节点不留下空位置或完整五槽背景，整条现有节点居中。
已有塔数未达到下一门槛时照常显示实际进度，不把 N 个节点全亮解释成 Charge III。

10.2 形状与尺度
第 1／3／5 节点：小菱形，约 7–9px。
第 2／4 节点：小圆点，约 4–5px。
相邻节点中心距默认 30–34px，桌面可轻增；五节点整体视觉宽约 160px，含两侧余量。
主轨高度约 24–28px，少节点时按相同节奏缩短总宽，单节点仍具有可靠轻点命中范围。
细线串接实际存在节点，阵营色为亮光，亮芯白色仅短促出现。
屏幕上方中央，位于安全区之下，不随战场旋转。手机和桌面均显示。

10.3 点亮和文字
R = 当前飞弹 Relay Count。前 R 个现存节点点亮，其余为未激活状态。
新飞弹 R=0，不把现有塔数自动点亮。
短文本使用“中继 R/5 / Relay R/5”，分母恒为 5；N 通过实际节点数量表达。
Charge 0 不显示三级技能名称；可仅在主动轻点时显示简短 Relay 0/5。
I：轨下显示“Charge Ⅰ · 扩张 / Charge Ⅰ · Expansion”。
II：轨下显示“Charge Ⅱ · 切割 / Charge Ⅱ · Crosscut”。
III：轨下显示“Charge Ⅲ · 清洗 / Charge Ⅲ · Purge”。
每个等级状态持续对应当前名字，第 2／4 次仍保留当前等级名称。
使用语言设置即时切换；英文仅展示英文名称，不夹带中文。
技能名称无框线、无卡片、无实色底，单行居中，字重中等，字号手机 12–14px、桌面 13–15px。
本版不增加点击后的详细能力说明、技能弹窗或额外说明面板。

10.4 透明状态机
Idle：轨线／未亮节点 opacity 0.15–0.25，已亮节点 0.25–0.35，文字 0.15–0.25；无背景面板。
Active：轨和文字约 0.9–1.0，不用长时间纯白；80–120ms 淡入。
保持：1.0 秒。
Fade：1.0 秒 ease-out 降回 Idle。
新进度再次发生时从当前值平滑回亮并重新计时，不叠多个淡出定时器。
轨与技能名称一起淡入、保留、淡出；升级时名字下方可有 120–180ms 极细光掠，属于文字发光而非边框。
触控聚焦仅让现有内容清晰，不展开额外信息。

10.5 瞄准期间与生命周期结束
开始拖拽后 HUD 不响应轻点，也不自动展开文字；本段期间出现的非关键装饰激活延后到拖拽结束，真实进度状态正常更新。
新有效捕获发生于飞行时，捕获后可正常短亮；随后用户开始重发瞄准则按当前透明动画继续淡出，不新增遮挡。
飞弹链结束保留最终亮点约 0.6 秒，再用约 0.6 秒淡出。淡出后 R 复位为 0、技能名称清空，节点数仍按己方现存塔数准备下一枚飞弹。
若期间发生 Turn 切换，先退出旧方展示，再更新到新方 N 与 R=0；旧淡出回调不可覆盖新方状态。
退出对局立即清空轨状态。
先锋移动中继不点亮此轨。

10.6 输入穿透
HUD 的轻点区紧贴主轨，桌面／手机只绑定这一区域，技能文字 pointer-events:none。
实现共享指针仲裁：按下先记录候选；移动超过现版战场拖拽阈值时转交战场，并使用初始按下坐标；抬起仍为轻点且战场未处于拖拽状态才激活 HUD。
没有整屏透明拦截层，也没有独立背景卡片。
已开始战场拖拽的指针经过 HUD 区仍归战场，不重新捕获。
不要用 HUD stopPropagation 吞掉整个战场手势；依据现有输入控制器集成。
命中区域在 safe-area 内，尺寸至少为主轨高度附近的 32–36px，单节点宽至少 44px。

10.7 已使用塔标记
仅当前飞弹 visited 集合中的塔显示极细缺口环／短刻度，低亮度阵营色。
保持塔体与保护区正常亮度。
重复撞塔时标记闪 70–100ms，配实体火花与反弹音。
飞弹结束与退出对局清除所有临时已用标记。

十一、操作菜单、布局与地图视觉

11.1 一级与二级结构
先锋附近一级入口为“移动 / Move”与“行动 / Action”，排列整齐，有一致锚点。
移动点击后直接进入拖拽瞄准，不建立移动二级操作列。
行动点击后通过一条短连接线引出统一竖列：发射飞弹、建立据点／重新部署据点、摧毁据点，沿用现版资格与禁用逻辑。
返回位于操作列附近，触控区域至少 44×44px。
连接线连接整列锚点，不为每项生成一条长线。

11.2 竖列数值
列宽默认 132px，可在 116–144px 内适配。
每项高度至少 44px，间距 6–8px；圆角 8–10px，文字／图标统一基线。
半透明深底仅用于按钮自身，细描边与短高亮反馈，保持现有阵营科技风。
不可用项清楚降低亮度，简短理由按现版说明，不要求玩家先点击才知道无法执行。
开始拖拽、实际发射、切 Turn、打开设置、进入终局时按钮与连接线一起收起。

11.3 位置与安全区
菜单避开先锋实体、Home Indicator、刘海、安全边距和底栏。
空间不足时整列换侧或上下平移，保持同宽竖列；最小距物理边缘 12px 加 safe-area。
手机保留现版独立小底栏，不让信息面板扩大侵占战场；桌面保持更舒展间距。
敌方 HP 浮窗保留现版可开关功能，默认与显示规则沿用现版。
不新增开启下一回合前的“准备”确认步骤。

11.4 地图状态层级
Stable：清楚阵营底色，亮度克制，保留网格。
Temporary：同阵营低饱和底色与稀疏轻斜纹，红蓝仍可快速区分。
Protected：突出有效保护区域外边界，内部纹理极淡，减少逐格粗方框。
同方保护区域相邻或重叠时，视觉呈联合区域边界；内部不重复画多层粗线。
Pending：原属阵营底色仍保留，争夺方色细边界／轻光沿边，约 1.6–2.2 秒缓慢呼吸。
Pending 成员变化在地图事务结束后立即反映，不等到到期才显示新增区域。
先锋保持圆形，据点保持方形。重合时可加细亮边分离轮廓，两个实体均可识别。
规则提示主要依靠状态、形状与局部事件，不用长期全屏霓虹。

十二、自定义轮数与终局页面

12.1 对局选择
快速 Quick：10 Round。
标准 Standard：14 Round。
长局 Long：18 Round。
自定义 Custom：1–100 Round，整数步进 1，初始默认 14。
四项在手机使用 2×2 网格，桌面可沿用网格或更宽布局，选中状态一致。

12.2 Custom 控件
选择自定义后在当前面板内展开轮数滑杆，无二级弹窗。
实时显示整数，数字支持点击输入，也可附小型加减微调；拖动是完整支持的主要输入之一。
输入空值、非整数或超范围时显示短内联提示，在有效提交前保持最近合法值；失焦时整数规范化并裁剪到 1–100。
开始对局时一次提交 Round Limit，比赛中滑杆不修改当前局。
保留语言、音量、音效偏好、动态偏好和最近合法 Custom 数值。
首次无保存值时使用 14；切预设不会抹掉最近 Custom 值。

12.3 显示与结果
所有 HUD、菜单和结果适配 ROUND 100 / 100，保持三位数数字宽度。
1 Round 到期正确结算；100 Round 不出现 101/100。
平局显示“平局 / Draw”，双方均不作为败者。
胜利显示现版胜者信息，双方共用中性 Match Complete 音效风格。
返回主菜单、再来一局、重新开始均使用明确状态命令，清理旧局后创建或退出。

十三、聚能、飞行与中继反馈

13.1 统一语义
聚能中心是捕获塔中心，飞弹位置与中心一致。
一个有效捕获产生一个 relayCaptured 规则事件，同时附旧等级、新等级、计数、塔 ID 和反馈组 ID。
第 1／3／5 次为升级聚能，第 2／4 次为进度确认。
从已有 v0.4.0 动画与音效模块增量升级，保持连贯语言。

13.2 第 1 次：Charge I
据点周围约 0.8–1.0 格范围出现 6–8 个粒子，约 40ms 由透明变清晰，120–160ms 向塔中心收缩。
单个细环向内闭合，中心短亮，整体约 180–220ms。
声音短促上扬吸能与轻定音，约 180–220ms。
顶部第 1 菱形点亮，显示 Charge Ⅰ · 扩张。
不抖屏，不 Hit Stop。

13.3 第 3 次：Charge II
范围约 1.1–1.4 格，10–12 个粒子，两层收缩，短十字方向光纹提示切割能力。
整体约 240–280ms，核心比 I 更清晰，保持小范围。
声音较 I 音高略升、厚度略增，结束为短确认重音。
顶部第 3 菱形升级点亮，显示 Charge Ⅱ · 切割。
不抖屏，不 Hit Stop。

13.4 第 5 次：Charge III
据点周围约 1.5–2 格圆周范围出现 14–18 个粒子。
前 60ms 从透明显现，分内外层；外层先向中心加速，内层延迟约 40ms。
中心逐渐亮起，粒子到达后产生短高亮核心，两层细环向内收缩，最后一个短向外脉冲。
整体约 300–340ms。
声音低声吸能 → 快速上扬 → 很短的充满定音，表示武器充满而不是爆炸。
顶部第 5 菱形点亮，显示 Charge Ⅲ · 清洗。
不抖屏，不 Hit Stop。

13.5 第 2／4 次
100–140ms 短吸入，3–5 个轻粒子或短内环，对应圆点点亮。
声音一次轻确认，当前等级名称不变。
保持现有重新弹射操作，等待输入的规则状态与升级捕获完全相同。
五塔上限与同塔一次规则下没有正常第六次新塔中继，本版不新增第六节点或更高等级表现。

13.6 重发与飞行
I 重发环比基础稍亮；II 增加轻外环和短方向能量纹；III 核心向前释放并形成较亮、略粗但短的尾迹。
尾迹使用阵营色、中心细亮芯，短时间衰减；不成为遮住格子的长光带。
每次实际重发播放一次对应发射音；飞行不持续播放循环轰鸣。
蓄能等级不改变飞行速度、反弹物理与瞄准手感。

13.7 捕获／携带角色
实际进入携带状态时角色旁产生短能量弧，视觉位置按现版与飞弹绑定。
声音一个短 snap，不循环。
每次现版规则成立的独立伤害均显示 -1 HP 或真实伤害数字并播放伤害反馈。
避免用长绳、链条或光束占据地图，绑定主要由共同运动与局部能量弧表达。

十四、最终染色、十字与攻城表现

14.1 普通结束
基础：3×3 中心短爆发与格子起落。
I：5×5 更宽但克制的扩张波。
II：3×3 中心冲击，四向十字快速传播。
III 普通结束：5×5 强核心加同样十字，保持明显高能级，强度低于实际摧塔。
视觉染色覆盖与规则合法目标一致，跳过受保护格。

14.2 十字传播
中心冲击 → 四向快掠 → 最终地图状态反馈。
主传播默认 220ms，可在 180–240ms 内调整，尾光约 100–160ms 衰减。
一格宽颜色变化，叠加更细亮芯，不用整条纯白条遮住地图。
远端速度按距中心归一化时间，整图四方向同期结束；规则早已原子提交。
只表现逻辑行列目标，不额外绘制斜线。

14.3 Protected 掠过
受保护格保持原色，出现一次 60–100ms 很轻侧光／护盾纹理。
光继续经过并到达其后合法格，不表现撞墙停止。
可有统一轻尾音，由本次十字组调度；不按每个 Protected 格发声。
颜色未变但光经过的区别可识别。

14.4 真实断联／恢复
只依据提交前后真实 Stable / Temporary 变化生成区域反馈。
真实断联：区域由近至远轻衰减，颜色仍保留原阵营；一次系统尾音。
恢复连接：轻恢复波与一次短确认。
十字划过但仍存在受保护桥梁保持四连通时，不播放“断联成功”。
同次染色引出的断联作为主事件尾层，声音和震动不独立再叠一次爆炸。

14.5 Charge III 实体摧塔
直接命中点第一帧短亮；塔体原位高亮约 50ms，接短 Hit Stop。
塔裂解为约 8–12 个几何碎片，向外短散 180–260ms 后淡出；一圈细冲击环。
中心 5×5 格从内向外浮起、落下、变色；随后四向十字与必要真实断联波。
实际摧塔主震动 2–3px，120–150ms，单次。
主声音 Siege Impact：短金属／能量破裂 + 低频短爆破 + 轻碎片尾声，合成为一个主音效，约 400–500ms。
中心、碎片、格子起落、十字与断联可有多个视觉层，共用一次主要声音与震动。
减少动态效果设置下使用简化短闪、颜色与必要碎塔提示，不执行屏幕抖动和 Hit Stop。

十五、Feedback Director、Hit Stop 与音效管理

15.1 同时与连续的唯一口径
同时合并按“同一规则事务／同一冲击组”识别，使用 eventGroupId。
同一攻城衍生碎塔、最终染色、十字、断联属于同组；同一批成长与同一批吞并可分别有自己的组。
连续真实反弹与连续合法 HP 扣减各有 eventId，即使时间非常接近也不是同一事件，保留逐次反馈。
不以通用 100ms／200ms 静音冷却吞掉真实碰撞。
同帧不同物理碰撞仍按独立事件记录；声音可降低叠加音量，必要数字和局部反馈保留。

15.2 一个组的输出
一个规则组允许多个必要局部视觉层，最多一个主要音效、一个轻次要提示、一次主要震动、一次该组 Hit Stop。
主音效优先级：终局 > 攻城 > 角色伤害 > 最终能量爆发／十字 > 升级 > 普通反弹／轻 UI。
攻城合成音已包含破裂与爆破层，其同组不追加另一份普通爆炸主声。
真实伤害数字始终保留；若处于攻城组，音色纳入主声或轻提示，避免多个主声争抢。
不同时间独立伤害、反弹仍各自播放，轻压缩与音量调节控制总负载。

15.3 Hit Stop
普通反弹：0ms，不屏幕抖动。
独立角色伤害：默认 20ms。
Charge III 实体攻城：默认 40ms。
同组用最大值一次执行；不同事件在已有短停顿中发生时不把时长累加成长冻结，保留局部声音和数字。
冻结物理推进，渲染与短闪可以继续；恢复时重置物理时钟基准，不把冻结时间计入 accumulator，不补帧快进。
减少动态效果时 Hit Stop 与震动关闭，必要数字、实体状态与颜色保持。
本版不在普通反弹、成长、聚能或十字经过塔时增加暂停。

15.4 震动
现版轻伤害／爆发震动保留，按 Director 最大值仲裁。
较弱新冲击不覆盖尚未结束的较强主冲击；同组不累加位移。
屏幕坐标震动只影响战场表现，不移动 DOM 操作按钮，也不改变输入逻辑坐标。
普通反弹用局部火花即可。

15.5 声音库与层次
继续复用 v0.4.0 的 UI 点击、移动弹射、飞弹发射、反弹、先锋中继、三级聚能、携带、伤害、普通／较强爆发、建塔、成长、断联、恢复、吞并、手动拆塔、重新部署、攻城、交接、终局声音。
将第 2／4 次中继确认与十字扩散加入现有事件音色体系，可通过现有音效组合实现，不要求大量新增文件。
背景持续音保持现版；飞行与携带不新增循环响声。
终局使用中性 Match Complete：两个短上扬音加稳定定音，约 400–650ms；平局同样用中性收束，可降低上扬幅度。
不同时播放“红方胜利乐”和“蓝方失败乐”。

15.6 音量与负载
统一 Master Gain 与现版音量设置，声音节点随播放结束断开。
常规事件约束同时发声数默认最多 8 个短声部；持续反馈大量叠加时优先压低或替换低优先级 UI／装饰声部。
真实反弹与真实伤害事件不因简单冷却被删除，采用较轻音量、短包络与限幅／压缩维持可辨性。
禁止排队后在事件结束很久才补播大量旧声；后台暂停时丢弃过期声音队列。
用户音效 OFF 或音量 0 的选择保持，设置更改不改写独立的系统动效偏好。

十六、移动端音频与对局状态修复

16.1 手机无声的排查
现版已有首次交互解锁与恢复逻辑，先复现并定位故障：Context 状态、资源解码、Gain 值、用户偏好、后台挂起、输出路由及环境限制。
在直接用户交互调用栈中初始化／resume AudioContext，如 Start、音效开启、用户再次操作；避免先 await 无关操作再尝试解锁。
处理 suspended、interrupted（平台支持时）及 closed；closed 时按安全流程重建。
visibilitychange、focus 回来时尝试可用恢复，若浏览器仍需用户手势则等待下一次真实点击，不自动重播旧声音。
资源使用现版合成音或经目标设备验证可解码的格式；解码失败有降级短合成音。

16.2 设置 UI
“音效已启用”是用户偏好；“等待点击启用声音”是浏览器解锁状态，二者分别表示。
可播放状态以 Context 与加载情况判定，不宣称设备喇叭实际听到。
解锁待处理时用简短内联状态，不阻断比赛；提供音效按钮重试，成功后播放一次轻确认。
静音状态不强行自动开启。

16.3 返回主菜单
问题根因是旧 match winner 被界面更新重新识别，隐藏结果框不足以退出。
使用显式 appScreen/menu 与 match lifecycle：menu → playing → resolving → gameOver → menu。
返回命令一次性终止 match，清除 winner／result、active match 引用、输入、飞弹、角色、塔、领地、争夺、Turn、Round、Charge、HUD、临时动画与反馈。
RAF、timeout、音频节点、事件订阅与回调全部取消或失效化。
为每局分配 matchId／generation，所有异步结果应用前校验所属局。
保留语言、音量、音效、动效偏好和 Custom 数值。

16.4 幂等与第二局
连续双击返回只执行一次有效退出；退出后立刻 Start 创建全新状态。
旧胜利状态不能重新打开结果页；旧淡出不能清空新 HUD；旧声音不能恢复播放；旧区域吞并不能影响新地图。
再来一局与重新开始采用同一清理基础，按现版约定保留所选模式并创建新局。
Game Over 后继续触摸战场不产生移动或行动。

十七、模块职责、数据结构与性能

17.1 规则层
负责塔资格、成长、保护、四连通、争夺、Charge、伤害、终局与合法命令；纯计算尽量独立于渲染与音频。
推荐集中 RulesConfig，包含能力表、MAX_TOWERS、轮数范围及现版未改参数。

17.2 状态层
App：screen、settings。
Match：id、phase、activePlayer、turnSerial、round、roundLimit、winner/result、map、players、towers、pendingRecords。
Projectile：logicalId、owner、position、velocity、phase、visitedRelayTowerIds、carriedPlayer、sourceExitGrace。
Tower：id、owner、createdSerial、growthStage、age、有效覆盖／可派生来源。
PendingRecord：id、claimant、originalOwner、sourceTowerIds、dueTurnSerial、当前成员／延续定位。
HUD：activeOwner、visibleNodeCount、relayCount、derivedCharge、displayState、transitionToken。
Set 在存档／调试序列化时转数组，恢复时去重并校验 ID。
具体名称按项目架构调整，语义保持。

17.3 输入层
统一处理拖拽、轻点、HUD 仲裁、菜单、取消与回合锁定。
屏幕坐标经 safe-area、缩放和战场旋转转换到逻辑坐标，碰撞和十字仍用逻辑地图。
避免为每个节点单独创建与战场冲突的拖拽系统。

17.4 表现层
BattleRenderer：格子、先锋、塔、保护／争夺边界。
Effects：聚能、十字、碎片、数字、波纹和尾迹。
Feedback Director：事件组、声音、震动、Hit Stop。
HUD／菜单：订阅规则结果，不自行推导另一份能力或目标集合。
AudioManager：解锁、音量、节点生命周期、后台恢复。
每个单元有明确输入输出，复用现版框架，不为本版引入无关大规模重构。

17.5 批处理
成长、十字、吞并按地图事务批量处理。
每个事务完成一次必要保护和连通重算；可按依赖阶段进行多次内核计算，但不对每格触发框架 setState、DOM 音效或完整 flood-fill。
动态 Pending 更新发生于逻辑地图变化事务，不每帧 flood-fill。
反馈 diff 基于事务前后状态，不基于动画每帧推断。

17.6 流畅与生命周期
目标常规目标设备 60fps，固定步长物理与有界子步，沿用现版速度稳定性。
粒子使用复用／池化，默认同时活跃装饰粒子上限 180，优先删装饰尾光，关键角色数字、节点和规则边界保留。
不使用每格 DOM 动画实现全图十字，沿用战场渲染器。
100 Round 内计时器、监听器、音频节点和动画对象释放，资源用量趋于稳定。
浏览器切后台暂停输入与物理时间推进，返回不补播、不快进。
系统减少动态设置仅影响表现，玩法不变；语言／音量修改不覆盖该偏好。

S10 100 Round 场景包含移动、建塔、重新部署、拆塔、中继、携带、动态争夺、声音与结果；监测存活对象与监听器，无随轮数无界增长。
S11 模拟压力场景覆盖合法拓扑变化，不只连续跳过回合。

二十、由编写者自行补定的疑问与处理

本节是用户允许自行思考处理的边界记录，以下选择已经纳入本文，无需阻塞出具文件。

A. 动态争夺被切成几个子块后，哪些继续争夺？
处理：所有包含有效延续成员且仍同色 Temporary 的子块继承原来源与时点；恢复稳定的子块解除。避免重新变成面积快照，也避免切一次就无条件解除争夺。

B. 多条争夺记录连接到同一块，计时如何处理？
处理：采用最早到期且来源仍有效的记录；新接入面积共享该时点，失效记录清除，后加入不延长对手救援窗口。

C. 恢复稳定后再断联，是否恢复旧争夺？
处理：恢复稳定即解除旧关联；再次断联需新合法触发，或连接仍有效的被争夺 Temporary 块。被取消的争夺不长期潜伏。

D. 动态区域需要定位信息，会不会又变成快照吞并？
处理：历史成员仅追踪区域延续，目标始终重新寻找完整当前连通块，新增合法连接面积全部纳入。

E. 塔的几何范围重叠，会不会出现敌方格被两边同时保护？
处理：同方来源叠加；敌方已保护格保持颜色和保护优先权。几何候选覆盖不自动创造异方共同保护。

F. 当前只有零塔时，顶部轨显示什么？
处理：隐藏节点与技能名，保留全部基础飞弹玩法和现场反馈；零塔不展示虚假的升级节点。

G. 只有两塔且两个节点全亮，如何防止误认为满级？
处理：节点数表达可用塔资源，R/5 表达五次门槛总进度，等级明确为 I；1／3／5 关键形状保持原序号。

H. 进度轨的节点是否绑定具体塔？
处理：节点是中继顺序位，地图塔用 visited ID 标记。无需给顶部每个节点添加具体塔标签。

I. “清洗”的英文以及实际能力如何限定？
处理：英文采用 Purge；名称只对应 5×5、十字与实体攻城，不代表全图任意格翻色、远程拆塔或新伤害。

J. 原草稿中的 HUD 点击详细说明如何处理？
处理：按用户最新确认移除说明展开，点击只短时提高清晰度，三级名称在轨下无框出现。

K. 未到下一等级所需塔数，是否额外提示“还差几座塔”？
处理：本版不增加详细提示行；实际节点数量与 R/5 已表达资源和进度，保持轻量。规则说明仍由已有游戏入口承载。

L. 飞弹链期间能否部署改变节点数量？
处理：按现版行动互斥保持链内不能另行部署或拆塔，消除 UI 塔数和历史 relay 数矛盾。异常存档／调试状态由校验处理，不改变正式规则。

M. 拖拽穿过 HUD 与轻点激活如何同时满足？
处理：共享输入仲裁，超过现版拖拽阈值即交给战场，保留起点；技能文字不接收指针，HUD 不铺大透明层。

N. “成长只对未被保护的格子”是否包含己方已保护格？
处理：已己方保护格颜色本来相同，不重复染色动画；新增己方保护来源仍登记。敌方 Protected 一律保持原色。

O. Hit Stop 与连续真实反馈冲突如何处理？
处理：每次真实事件保留声音／数字，冻结不累加成长停顿，物理恢复不补帧；普通反弹完全不暂停。

P. 轮数满额同分是否采用旧加时？
处理：按用户确认平局收束，删除加时分支与 101/100，终局比较其他既有非同分条件仍保留。

Q. 原草稿把五塔上限／成长染色当新增，如何指导开发？
处理：标为保留并完善，复用现版规则入口，重点补重叠来源、完整复查与测试，不重写无关内核。

R. 未在本次重新给数值的物理与基础规则如何避免随意猜测？
处理：第 1.4 要求从现版代码提取基线配置，不采用开发者自行估值；本次所有改变均由上述章节定义。

本确认版中新增玩法与本次用户确认的表现方向已明确；剩余现场数值调优与既有规则参数读取按本文执行。不存在需要用户再次作出选择、才可完成本规格的待定问题。
