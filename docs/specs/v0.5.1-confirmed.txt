《Website Game Development》
v0.5.1 开发规格文档（完整更新版）
基于版本：v0.5.0
文档性质：规则修正 / 平衡性修正 / UI识别性修正 / 新增轻量回血机制
目标：在不破坏 v0.5.0 既有核心机制的前提下，修复 HP 扣减判定、十字切割与保护格交互、保护格视觉表达、顶部五节点进度轨的回合提示行为，并新增“部署 / 重新部署据点恢复 1 HP”的主动回血机制，使攻击、领土、防守、据点重新部署之间形成更健康的策略循环。

============================================================
一、版本目标
============================================================

本版本为 v0.5.0 的小版本修正与平衡补丁，版本号建议：

v0.5.1

本版本只完成以下五类内容：

1. HP 领土扣减判定修正
   只有角色脚下当前格子的阵营颜色属于对方时，才触发该项 HP 扣减。
   对方普通格、稳定格、保护格均属于“对方领土”。
   中立格不属于对方领土。

2. 飞弹携带角色 + 爆炸染色后的 HP 结算顺序明确
   如果飞弹携带对方玩家到某一格并发生爆炸染色，则：
   【先完成爆炸和最终染色，再根据爆炸完成后的最终脚下颜色执行领土 HP 判定。】
   因此，如果爆炸刚刚把角色脚下格子染成攻击方颜色，被携带的对方角色也会因此扣血。

3. 十字切割与保护格交互修正
   十字切割某方向遇到保护格时，该方向立即停止。
   保护格本身不受影响。
   不允许穿越、跳过保护格继续切割后方格子。

4. 保护格 UI 恢复逐格锁定
   每个保护格独立显示锁定状态。
   不再使用整片“大保护区域”视觉。

5. 新增回血机制
   玩家成功在脚下：
   - 建筑 / 部署据点；
   - 重新部署据点；
   都会立即恢复 1 HP。

   回血动效：
   - 角色旁边浮出绿色“+1 HP”；
   - 角色自身短暂高亮；
   - 不增加额外回血音效，因为部署据点本身已有对应音效，避免重复音效造成听觉负担。

6. 顶部五节点进度轨
   每个新回合开始时自动完整显现并高亮一段时间，再平滑淡回低透明状态。

============================================================
三、核心设计原则
============================================================

本次修改的平衡目标：

A. 攻击仍然有效
飞弹将对方玩家带入爆炸区域并将脚下染成己方颜色后，应该可以正常触发领土 HP 扣减。

B. 不能让攻击流成为唯一最优解
通过“部署 / 重新部署据点恢复 1 HP”，给予玩家主动恢复的策略渠道。

C. 回血必须与战术行为绑定
不是自动回血，不是每回合回血，也不是站在己方领土回血。
只有真正完成据点部署 / 重新部署，才恢复 HP。

D. 回血不能绕开 HP 上限
恢复后 HP 不得超过角色最大 HP。

E. 所有状态必须一次结算
同一个部署动作只能触发一次 +1 HP。
不能因动画、重渲染、事件重复监听而多次回血。

F. 视觉反馈明确但克制
回血需要让玩家清楚看到，但不能增加大量粒子、震动或多重音效。


============================================================
四、修改项 1：HP 领土扣减判定
============================================================

【最终规则】

角色触发“脚下领土 HP 扣减”的唯一领土条件：

角色当前脚下格子的 owner / team 属于对方阵营。

即：

isEnemyTerritory =
    tile.owner === opponentPlayerId

或：

isEnemyTerritory =
    tile.team === opponentTeam

保护 / 稳定 / 不稳定仅属于格子状态，
不改变格子所属阵营。

------------------------------------------------------------
4.1 判定表
------------------------------------------------------------

以蓝方角色为例：

蓝色普通格
→ 不触发领土 HP 扣减。

蓝色稳定格
→ 不触发。

蓝色保护格
→ 不触发。

红色普通格
→ 触发。

红色稳定格
→ 触发。

红色保护格
→ 触发。

中立格 / 无阵营格
→ 不触发。

红方完全镜像处理。

------------------------------------------------------------
4.2 禁止错误写法
------------------------------------------------------------

禁止：

if (tile.owner !== currentPlayerId) {
    damage()
}

因为：
“不是己方”不等于“敌方”。

必须显式判断敌方 owner。

推荐：

function isEnemyTerritory(tile, currentPlayer) {
    if (!tile || tile.owner == null) return false;
    return tile.owner === getOpponentId(currentPlayer);
}

------------------------------------------------------------
4.3 所有权与状态解耦
------------------------------------------------------------

建议数据结构逻辑清晰：

tile.owner
tile.stability
tile.protected

例如：

{
    owner: "red",
    stability: "stable",
    protected: true
}

仍然是红方领土。

protected = true
不能改变 owner。


============================================================
五、修改项 2：飞弹爆炸染色后的领土 HP 结算
============================================================

这是本版本必须明确的结算边界。

【最终确认规则】

当飞弹：
1. 捕获 / 携带对方角色；
2. 飞到某个位置；
3. 在该位置触发爆炸；
4. 爆炸将周围格子染成飞弹所属方颜色；

如果被携带角色最终脚下的格子，在爆炸染色完成后变成了对方颜色：

→ 该角色需要正常触发领土 HP 扣减。

即：

【飞弹爆炸造成的新染色，可以立即参与本次最终 HP 判定。】

------------------------------------------------------------
5.1 正确结算顺序
------------------------------------------------------------

一次“携带角色的飞弹爆炸事件”必须按照以下顺序处理：

Step 1
确定飞弹最终碰撞 / 爆炸位置。

Step 2
确定被携带角色最终落点。

Step 3
执行飞弹爆炸效果。

Step 4
执行爆炸范围领土染色。

Step 5
完成所有本次爆炸造成的地形状态更新。

Step 6
读取被携带角色脚下【最终状态】格子。

Step 7
如果该格子属于对方阵营：
→ 执行领土 HP 扣减。

Step 8
完成本次飞弹事件剩余结算。

核心原则：

【HP 判定看的是爆炸与染色完成后的最终棋盘状态。】

------------------------------------------------------------
5.2 示例 A：爆炸前是自己的颜色，爆炸后变敌方颜色
------------------------------------------------------------

蓝方飞弹携带红方角色。

落点原本：
红色。

蓝方飞弹爆炸后：
该格被染成蓝色。

最终：
红方角色脚下 = 蓝色。

结果：
→ 红方扣除领土 HP。

------------------------------------------------------------
5.3 示例 B：爆炸前已经是敌方颜色
------------------------------------------------------------

蓝方飞弹携带红方角色。

落点原本：
蓝色。

爆炸后仍是蓝色。

结果：
→ 红方扣除领土 HP。

------------------------------------------------------------
5.4 示例 C：爆炸后仍不是敌方颜色
------------------------------------------------------------

如果由于保护格、特殊规则或其他合法原因：

爆炸完成后，
红方角色脚下仍然不是蓝色。

结果：
→ 不触发该领土 HP 扣减。

------------------------------------------------------------
5.5 禁止双重领土判定
------------------------------------------------------------

不能：

爆炸前检查一次
+
爆炸后再检查一次

导致同一次事件中因为脚下领土被扣两次。

本次飞弹事件只执行一次最终领土判定。

即：

resolveMissileExplosion()
→ applyTerritoryChanges()
→ evaluateStandingTerritoryDamageOnce()

必须是“一次最终检查”。

------------------------------------------------------------
5.6 与其他飞弹伤害分离
------------------------------------------------------------

如果现有飞弹事件本身还有其他合法 HP 伤害来源：

应保持原规则。

“飞弹自身伤害”
与
“最终脚下敌方领土伤害”
是两个不同来源。

是否同时发生，应按既有规则正常结算。

本版本只明确：
爆炸染色后的最终脚下颜色可以触发领土 HP 判定。


============================================================
六、修改项 3：新增据点部署回血机制
============================================================

【核心规则】

玩家成功完成以下任一行为：

A. 在脚下建筑 / 部署据点；
B. 重新部署已有据点；

都会恢复：

+1 HP

------------------------------------------------------------
6.1 回血数值
------------------------------------------------------------

每次合法、成功完成的部署 / 重新部署：

healAmount = 1

最终：

currentHP = min(maxHP, currentHP + 1)

不得突破最大 HP。

------------------------------------------------------------
6.2 什么情况算“成功部署”
------------------------------------------------------------

只有游戏逻辑已经正式确认并写入棋盘状态的部署行为，才触发回血。

即：

玩家选择部署
→ 目标合法
→ 确认部署成功
→ 据点真正生成 / 重新部署完成
→ 执行 +1 HP

以下情况不回血：

- 只是点击部署按钮；
- 只是进入部署模式；
- 预览部署位置；
- 拖动但取消；
- 目标位置非法；
- 部署失败；
- 被规则阻止；
- 用户退出操作；
- 没有真正改变据点状态。

------------------------------------------------------------
6.3 新部署与重新部署
------------------------------------------------------------

以下两者完全一致：

首次 / 新增合法据点部署
→ +1 HP

已有据点重新部署到脚下
→ +1 HP

如果现有规则允许玩家在达到据点数量上限后选择某一个据点重新放置，
那么成功重新放置后同样恢复 1 HP。

------------------------------------------------------------
6.4 最大 HP
------------------------------------------------------------

如果：

currentHP < maxHP
→ 恢复 1 HP。

如果：

currentHP === maxHP
→ HP 数值保持 maxHP。

不允许：

maxHP + 1

也不允许通过连续重新部署永久叠高最大生命。

------------------------------------------------------------
6.5 满血部署时的反馈
------------------------------------------------------------

如果玩家已经满 HP：

部署行为仍然正常完成。

但是：
- 不增加 HP；
- 不显示虚假的“+1 HP”；
- 不播放回血高亮。

因为实际 HP 没有发生变化。

据点本身的部署动效 / 音效照常执行。

------------------------------------------------------------
6.6 单次部署只能回血一次
------------------------------------------------------------

这是重要防 Bug 条件。

一次部署动作：

deploymentActionId = unique

回血只能绑定在：

onDeploymentCommitted

而不是：
- render；
- animationend；
- pointerup；
- state refresh；
- DOM 重绘。

不能出现：

据点生成一次
→ React / DOM 重绘三次
→ HP +3

推荐：

function commitDeployment(...) {
    ...
    const deployed = applyDeployment(...);

    if (deployed) {
        healPlayerFromDeployment(playerId);
    }
}

------------------------------------------------------------
6.7 部署回血与行动成本
------------------------------------------------------------

回血不会改变部署本身的成本。

即：
如果部署据点本来会消耗一次行动 / 对应资源，
仍然照常消耗。

不能因为“回血”：
- 返还行动；
- 免费部署；
- 增加额外部署次数；
- 跳过已有部署限制。

回血只是部署成功后的附加收益。

------------------------------------------------------------
6.8 回血与死亡状态
------------------------------------------------------------

如果角色已经进入正式死亡 / 被击败状态：

不能通过随后延迟触发的部署事件复活。

即：

if (player.isDefeated) {
    return;
}

只有仍处于可行动、未被判定死亡的玩家可以通过合法部署恢复 HP。

------------------------------------------------------------
6.9 推荐函数
------------------------------------------------------------

const DEPLOY_HEAL_AMOUNT = 1;

function healPlayerFromDeployment(playerId) {
    const player = getPlayer(playerId);

    if (!player || player.isDefeated) return;

    const before = player.hp;
    const after = Math.min(player.maxHp, before + DEPLOY_HEAL_AMOUNT);

    if (after === before) return;

    player.hp = after;

    triggerHealVisual(playerId, after - before);
}

============================================================
七、据点回血动效
============================================================

本机制需要清晰的视觉反馈。

不增加新的回血音效。

原因：
部署 / 重新部署据点已经有自己的音效。
回血与部署发生在同一瞬间。
额外增加 heal sound 容易产生音效重叠和听觉负担。

------------------------------------------------------------
7.1 “+1 HP”浮字
------------------------------------------------------------

成功恢复 HP 时：

在角色图标旁边出现：

+1 HP

颜色：
绿色系。

要求：
- 清晰；
- 明亮；
- 不刺眼；
- 与红蓝阵营颜色明显区分；
- 不使用巨大字体；
- 不遮挡角色；
- 不遮挡重要棋盘信息。

推荐动效：

初始：
opacity: 0
scale: 0.9
位置：角色图标侧上方

0–120ms：
快速出现
opacity → 1
scale → 1.0

120–650ms：
轻微向上漂浮约 8–16px

650–900ms：
继续上浮少量
opacity → 0

总时长建议：
约 0.8–1.0 秒。

不要持续太久。

------------------------------------------------------------
7.2 角色高亮
------------------------------------------------------------

回血同时：

角色图标进行一次短暂高亮。

推荐：

0–100ms：
角色边缘 / 外圈亮度提升。

100–300ms：
保持轻微高亮。

300–500ms：
恢复正常。

可以使用：
- 轻微绿色外发光；
- 或白绿混合高光；
- 或短暂亮度提升。

不能：
- 强烈闪屏；
- 大幅缩放；
- 大范围震动；
- 长时间绿色覆盖角色。

角色阵营识别必须始终保留。

------------------------------------------------------------
7.3 回血动效和部署动效的关系
------------------------------------------------------------

两者可以同时发生。

部署：
表现“据点生成 / 重新落位”。

回血：
表现“玩家获得 1 HP”。

但不能互相遮挡。

推荐层级：

棋盘格 / 领土
↓
据点
↓
角色
↓
角色回血高亮
↓
+1 HP 浮字

------------------------------------------------------------
7.4 无额外音效
------------------------------------------------------------

明确：

回血不调用新的音效。

不要：
playDeploySound()
+
playHealSound()

只保留已有：
playDeploySound()

视觉反馈承担回血提示。


============================================================
八、回血机制的平衡意义
============================================================

该机制的目的：

不是让玩家轻易回满血。

而是鼓励：
- 建立据点；
- 重新部署据点；
- 调整地图控制；
- 在进攻与恢复之间做取舍。

攻击型玩家可以通过：
飞弹携带 + 爆炸染色 + 敌方领土压制
造成持续威胁。

受压玩家则可以通过：
寻找合法部署机会
→ 调整据点
→ 恢复 1 HP
→ 同时改善战略位置。

因此形成：

攻击压力
↕
据点重新部署 / 恢复
↕
领土控制

三者循环。


============================================================
九、修改项 4：十字切割遇保护格立即中断
============================================================

【最终规则】

十字切割从触发中心向：

上
下
左
右

四个方向独立延伸。

每个方向：

遇到保护格
→ 立即停止该方向扫描。

保护格：
- 不被切割；
- 不被改变；
- 不允许穿透；
- 后方格子不继续处理。

------------------------------------------------------------
9.1 标准示例
------------------------------------------------------------

角色 → A → B → P → C → D

A = 普通格
B = 普通格
P = 保护格

结果：

A：处理
B：处理
P：不处理
C：不处理
D：不处理

------------------------------------------------------------
9.2 四方向独立
------------------------------------------------------------

上方遇保护格：
只停止上方向。

下、左、右：
继续正常处理。

禁止：
一个方向 break 导致整个十字函数 return。

------------------------------------------------------------
9.3 实现优先级
------------------------------------------------------------

单方向遍历：

while (insideBoard(tile)) {

    if (tile.protected === true) {
        break;
    }

    applyCrossCutEffect(tile);

    tile = nextTile;
}

保护判断必须发生在对该格应用十字切割前。

------------------------------------------------------------
9.4 边界
------------------------------------------------------------

角色紧邻保护格：

角色 → P → A

结果：
该方向没有任何格子被处理。

多个保护格：

角色 → A → P → P → B

结果：
只处理 A。

第一个 P 即终止。

保护格位于边缘：
正常结束，不得越界。


============================================================
十、修改项 5：保护格 UI 恢复逐格锁定
============================================================

【核心要求】

删除当前把多个保护格表现成“大区域”的视觉。

恢复：

【每一个保护格独立显示锁定状态。】

------------------------------------------------------------
10.1 视觉结构
------------------------------------------------------------

每个保护格保留原阵营颜色。

然后独立叠加：
- 四角锁框；
- 单格边缘高光；
- 轻微内发光；
- 克制的锁定纹理。

视觉含义：

“这一格被锁定。”

而不是：

“这一大片区域被保护。”

------------------------------------------------------------
10.2 稳定格 vs 保护格
------------------------------------------------------------

稳定格：
更平静。
弱强调。

保护格：
四角锁定信息更明确。
边缘亮度略高。

玩家在快速观察时必须能立刻区分。

------------------------------------------------------------
10.3 连续保护格
------------------------------------------------------------

[P][P][P][P]

必须看得出四个独立格。

每格：
拥有自己的边界和锁定 UI。

不能形成：
一整块连续外框。

------------------------------------------------------------
10.4 日常状态
------------------------------------------------------------

不要持续强闪烁。

如刚获得保护状态，可：

0.15–0.25 秒锁框收紧
+
一次轻微高光

然后回到稳定状态。

禁止：
- 高频呼吸；
- 大面积粒子；
- 强屏幕震动；
- 巨大锁头；
- 覆盖角色。


============================================================
十一、修改项 6：顶部五节点进度轨回合开始自动显现
============================================================

【最终行为】

每次新回合正式开始后：

顶部五节点进度轨：

约 0.2 秒
快速进入高可见状态；

约 2.5 秒
保持完整清晰、高亮；

约 0.8 秒
平滑淡回默认低透明状态。

总计约 3.5 秒。

------------------------------------------------------------
11.1 “高可见”不是实心遮罩
------------------------------------------------------------

要求：
- 节点清楚；
- 连线清楚；
- 当前进度清楚；
- 不大面积遮挡战场。

背景仍可以是科技感半透明面板。

------------------------------------------------------------
11.2 触发条件
------------------------------------------------------------

以下事件调用统一 showProgressTrack()：

A. 新回合开始
B. 点击进度轨
C. 五节点进度发生变化

------------------------------------------------------------
11.3 Timer 管理
------------------------------------------------------------

所有触发必须共用一个显示状态。

如果尚未淡出，又发生新触发：

- 清除旧 fade timer；
- 保持 / 恢复高可见；
- 重新计算 2.5 秒；
- 再执行淡出。

禁止多 timer 叠加。

------------------------------------------------------------
11.4 手机回合旋转
------------------------------------------------------------

手机端战场 180° 切换时：

进度轨属于固定 UI 层。

不要跟战场一起倒转。

正确时机：

完成 turn transition
→ 更新 currentPlayer
→ 更新进度
→ showProgressTrack()

不要在战场旋转一半时提前高亮。


============================================================
十二、统一结算顺序
============================================================

为了避免不同系统产生歧义，建议统一以下事件结算原则。

------------------------------------------------------------
12.1 飞弹爆炸携带角色事件
------------------------------------------------------------

1. 飞弹碰撞 / 停止
2. 确定最终爆炸点
3. 确定携带角色最终位置
4. 执行爆炸
5. 执行领土染色
6. 完成保护 / 稳定等合法地形结果
7. 获取角色脚下最终 tile
8. 执行一次领土 HP 判定
9. 执行其他剩余合法结算
10. 判断角色是否死亡
11. 结束事件

注意：
领土 HP 检查不得执行两次。

------------------------------------------------------------
12.2 据点部署事件
------------------------------------------------------------

1. 玩家发起部署 / 重新部署
2. 检查动作是否合法
3. 检查据点数量 / 重部署规则
4. 确认脚下目标
5. 正式写入据点状态
6. 消耗原本应该消耗的行动 / 资源
7. 部署成功
8. 如果玩家未满 HP：
   → HP +1
9. 播放部署原音效
10. 播放回血视觉（仅实际恢复 HP 时）
11. 完成事件

------------------------------------------------------------
12.3 同事件防重复原则
------------------------------------------------------------

同一个 action / event：

- 领土 HP 判定最多一次；
- 部署回血最多一次；
- 部署音效最多一次；
- 回血浮字最多一次。

============================================================
十四、必须避免的错误实现
============================================================

【错误 1】
踩中立格扣 HP。

错误。
中立不是敌方。

【错误 2】
踩敌方保护格不扣 HP。

错误。
保护不改变 owner。

【错误 3】
飞弹爆炸前先做领土 HP 判定，随后才染色。

错误。
本次明确要求使用爆炸染色后的最终格子状态。

【错误 4】
飞弹爆炸前、爆炸后各判定一次领土 HP。

错误。
只能最终判定一次。

【错误 5】
飞弹刚把脚下染成敌方颜色，但不扣 HP。

错误。
最终格子属于对方就需要扣。

【错误 6】
点击“部署”按钮立刻回血。

错误。
必须真正成功完成部署。

【错误 7】
进入重新部署模式就回血。

错误。

【错误 8】
部署失败仍回血。

错误。

【错误 9】
满血时显示“+1 HP”，但数值没增加。

错误。
没有实际恢复就不要显示回血视觉。

【错误 10】
部署后 HP 超过 maxHP。

错误。

【错误 11】
同一部署事件因为重复 render 回血多次。

错误。

【错误 12】
给回血新增独立音效并与部署音效叠加。

错误。
本版本明确不需要回血音效。

【错误 13】
十字切割遇保护格用 continue。

错误。
必须 break。

【错误 14】
十字切割穿越保护格后继续切后面。

错误。

【错误 15】
一个方向撞保护格导致四方向一起结束。

错误。

【错误 16】
连续保护格继续绘制成一个大保护区。

错误。

【错误 17】
进度条回合开始永久保持不透明。

错误。
只暂时高亮。
