# RICOCHET FRONT v0.6.1 开发规格
## Overload 控制范围规则补全 + Flux A 风格 UI / 动效精修

**目标版本：v0.6.1**  
**开发基线：GitHub `cianolu1125/ricochet-dominion` 当前 `main` 的 v0.6.0**  
**开发原则：在 v0.6.0 已稳定的规则、物理、输入、回合结构和 UI 架构上做增量升级，不推倒重做。**

---

# 0. 文档用途与执行原则

本文件是 v0.6.1 的开发权威规格。实现时应优先满足本文件明确写出的规则结果、时序、视觉识别和验收条件。

开发时采用以下思考顺序：

1. **先保证规则结果唯一、可测试、无歧义。**
2. **再保证画面准确表达规则状态。**
3. **最后做视觉强化和动效优化。**
4. 如果视觉效果与规则可读性发生冲突，优先保证规则可读性。
5. 如果动效美观与性能发生冲突，优先保留关键状态提示，削减非关键发光、粒子和装饰。
6. 除本规格明确修改的内容外，v0.6.0 已存在的规则、物理、伤害、Charge、中继、接管、收复、胜负、回合操作均保持不变。
7. 不要为了实现 v0.6.1 而重新设计 engine / physics 的整体架构；应在现有代码边界内增加清晰、可测试的状态与函数。
8. UI 风格采用已经确认的 **A：Flux 精修版**。它是当前 v0.6.0 深色科技风的升级，不是重新换皮。

# 1. v0.6.1 更新目标

v0.6.1 解决两个核心问题：

## 1.1 规则层

补全 Overload 后据点“原控制范围、失去控制、恢复、再次成长”的完整逻辑。

玩家必须能够理解：

- 据点最终仍以 5×5 为最大成长目标；
- Overload 会暂停当前保护与稳定根，但不会删除据点；
- Overload 期间被敌方染色的格子，根据其最终是否成为敌方稳定领土，恢复方式不同；
- 已被敌方真正稳定控制或据点锁定的格子，不允许在恢复瞬间直接抢回；
- 未被敌方锁定的失地，未来仍可以通过据点的正常成长逐步恢复；
- 邻近敌方据点可以利用 Overload 的窗口成长进来，并真实压缩 Overload 据点剩余影响范围。

## 1.2 UI / 视觉层

在当前 v0.6.0 深色科技风上升级战场可读性和动感：

- Stable / Protected / Unstable 三种基础格子保持静态，避免全图持续动画造成视觉疲劳；
- Unstable 不再使用渐变阴影或漂移阴影；
- Overload 必须显示剩余影响范围；
- Contested 据点和 Contested / Pending 领土必须有明确统一的争夺区域语言；
- 可用 Relay、Overload、Contested 等少量关键状态承担持续动画；
- 战场整体更有科技感、流畅感和生命力，但不能“满屏都在动”。

# 2. v0.6.0 必须保持不变的核心规则

以下属于回归保护项，v0.6.1 不得意外改变。

## 2.1 对局与胜负

- Quick / Standard / Long 固定为 10 / 14 / 18 Round。
- 初始 HP 与最大 HP 等于对应 Round 数。
- HP 归零立即结束。
- 完整一轮结束时领地达到 60% 获胜。
- 最终轮依次比较：领地面积 → HP → 据点数量；完全相同则平局。

## 2.2 回合

- 每回合有一次「移动」和一次「行动」，顺序自由。
- 行动可用于：飞弹、据点相关行动、拆塔。
- 手机热座：结束回合后先 180° 旋转，再执行新回合结算与表现。
- 电脑端维持固定视角。

## 2.3 据点

- 每方最多 5 座，出生据点计算在内。
- 普通新据点成长：
  - stage 0 = 1×1；
  - stage 1 = 3×3；
  - stage 2 = 5×5。
- 新建 / 重部署据点成功时 +1 HP，上限为该模式最大 HP。
- Take Over / Reclaim 不回血。
- 同阵营保护区可重叠，并集保护；移除其中一座后，仍由其他有效据点覆盖的格子继续受保护。

## 2.4 伤害与领地

- 只有敌方 **Stable 或 Protected** 领地具有 Territory HP 伤害资格。
- Unstable / Temporary、中立、己方颜色不造成 Territory HP 伤害。
- Temporary 仍保留颜色并计入面积。
- 飞弹携带最终爆炸遵循现有“先染色 / 更新地图，再做最终脚下伤害判定”。

## 2.5 Charge / Crosscut

- 同一飞弹每个己方据点 ID 仅可中继一次，再次碰撞时反弹。
- 1 / 3 / 5 次有效中继对应 Charge I / II / III。
- Crosscut 四个方向独立传播。
- 每个方向遇到第一枚 Protected 格立即停止，不穿越、不修改保护格及后方格子。
- 保持当前 Charge 面积、攻城、携带等规则。

## 2.6 v0.6.0 Overload / Take Over 基础规则

仍保留：

- 飞弹中继可以使据点 Overload；
- 如果据点中心被另一座正常己方据点保护，则触发 Shielded，不进入 Overload；
- 先锋移动中继不触发 Overload；
- Overload 据点暂停保护、稳定连接和中继资格；
- 对手获得完整一个 Turn 的利用窗口；
- 成熟 Overload 敌塔可被 Take Over；
- Take Over 后进入 Contested；
- 原主可 Reclaim；
- Contested 据点不成长、不保护、不参与中继、不可重部署撤除；
- Take Over 达成后保留据点原 stage；
- 满 5 塔时先原子选择替换一座正常己塔；
- Take Over / Reclaim 都属于终止型行动并结束 Turn。

# 3. 新增核心概念：据点“结构等级”和“当前影响范围”分离

这是 v0.6.1 规则实现的关键。

v0.6.0 主要通过 `stage` 推导 1×1 / 3×3 / 5×5。  
v0.6.1 以后，必须区分：

## 3.1 `stage`：结构等级

继续使用现有语义：

- `stage = 0`：结构成长到 1×1；
- `stage = 1`：结构成长到 3×3；
- `stage = 2`：结构成长到 5×5。

`stage` 表示该据点已经解锁到的理论成长尺寸。

## 3.2 `potentialRange(stage)`：当前结构允许的理论范围

以据点中心为中心：

- stage 0 → 半径 0；
- stage 1 → 半径 1；
- stage 2 → 半径 2。

这是据点当前结构等级允许控制的最大方形范围。

## 3.3 `maxPotentialRange`

任何据点长期最大目标都为 5×5，即 stage 2。

即使某些区域因为 Overload、敌方 Stable、敌方 Protected 被暂时失去，也不降低这座据点未来恢复到 5×5 的能力。

## 3.4 `influenceCells`：当前实际影响范围

建议为每座据点保存一个“当前实际影响格集合”。

可使用数组 / Set / 位图等实现；具体存储形式可由开发者选择，但必须满足以下行为：

- 普通完整 5×5 据点通常有完整 25 格；
- Overload 后仍保留“残余影响范围”的记录；
- 敌方稳定控制或锁定可让这个集合缩小；
- 它可以是不规则形状，不要求永远为标准正方形；
- 后续成长可以逐步把符合条件的格子重新加入。

不要仅用一个 `stage` 或一个矩形尺寸代替该集合，否则无法正确表示被敌方从一侧蚕食后的不规则边界。

# 4. Normal 据点保护的重新定义

Normal 据点的保护仍遵守原规则，但来源应与 `influenceCells` 对齐。

推荐逻辑：

```text
tower contributes protection only if:
- tower.state == normal
- cell ∈ tower.influenceCells
- cell 当前颜色 == tower.owner
```

多个 Normal 友塔可共同保护同一格，`protectedBy` 继续保存多来源。

Overload / Contested 据点不贡献保护。

---

# 5. 进入 Overload 时的规则

当现有规则判定某座据点进入 Overload：

1. 保留：
   - tower id；
   - owner；
   - slot；
   - stage；
   - tower entity；
   - 当前 `influenceCells`。
2. 设置：
   - `state = overloaded`；
   - 原有 Overload 生命周期字段继续工作。
3. 立即停止：
   - 保护；
   - 稳定根；
   - Relay 资格。
4. 不删除 `influenceCells`。
5. 进入 Overload 的瞬间，`influenceCells` 即成为该塔的 **残余影响范围**。
6. UI 立即用 Overload 专用边界显示该残余影响范围。

---

# 6. Overload 期间飞弹染色后的判定

Overload 据点原影响范围内的格子此时不受该塔保护，因此敌方飞弹可以正常染色。

关键区别在于染色后最终地图状态。

## 6.1 敌方颜色，但仍为 Unstable / Temporary

如果某格：

- 原属于该 Overload 塔的 `influenceCells`；
- 被敌方染色；
- 重算后为敌方 Unstable / Temporary；
- 未被敌方据点 Protected；

则：

- 此格仍保留在该 Overload 塔的 `influenceCells` 中；
- Overload UI 残余范围仍包含此格；
- 等塔恢复时，该格应立即恢复为据点原 owner 的颜色。

这表达的是：

> 对方只是趁保护暂停“染到了”，但尚未形成真正稳定控制。

## 6.2 敌方颜色并成为 Stable

如果某格在 Overload 期间变成敌方颜色，并且重算后已经是敌方 Stable：

- 该 Overload 塔立即永久失去这一次的残余影响权；
- 从 `influenceCells` 中移除该格；
- Overload UI 边界同步缩小；
- 塔恢复时不得立即将其染回。

即使该格没有敌方保护，它也已经从“恢复瞬间可直接回收”的范围中退出。

之后只能靠正常成长重新争取。

## 6.3 敌方 Protected / Locked

如果该格被敌方有效据点锁定 / 保护：

- 从 Overload 塔 `influenceCells` 中移除；
- 恢复时不能夺回；
- 后续成长也不能进入；
- 只有敌方保护来源消失后，才重新成为未来成长可尝试的格子。

---

# 7. 敌方据点利用 Overload 窗口成长

如果 Overload 据点附近存在敌方据点，原本由于我方 Protected 而无法成长到某些格：

当我方塔进入 Overload 后：

1. 我方保护失效。
2. 敌方据点在自己的正常成长阶段按照原成长规则执行。
3. 如果敌方成长合法进入我方 Overload 的残余影响格：
   - 敌方格被正常染色；
   - 敌方据点产生正常 Protected；
   - 我方 Overload 塔从 `influenceCells` 中删除对应格；
   - Overload 残余范围 UI 实时退让。
4. 两方控制边界由真实规则结果决定，不做“视觉假边界”。

这应产生明确的“敌方成长、我方残余影响范围被蚕食”的战术效果。

# 8. Overload 恢复规则

在原主下一次符合现有 Overload 生命周期的回合开始阶段恢复。

## 8.1 恢复时逐格检查 `influenceCells`

对当前仍保留在 `influenceCells` 的每格：

### A. 格子已经是己方颜色

- 保持己方颜色；
- 恢复后正常参与保护；
- 重新计算 Stable。

### B. 格子是敌方颜色且为 Unstable / Temporary

- 立即改回 tower.owner；
- 恢复保护；
- 重算连通和 Stable。

### C. 格子已经是敌方 Stable

- 不改色；
- 从 `influenceCells` 删除；
- 不恢复保护。

### D. 格子被敌方有效据点 Protected

- 不改色；
- 不允许恢复保护；
- 保持 / 删除于当前影响集合，最终效果必须等价于“此格目前不属于本塔实际影响范围”。

建议统一从 `influenceCells` 移除，使数据更干净。

## 8.2 恢复完成后

- `state = normal`；
- 恢复塔的 Relay、保护、稳定根资格；
- 重新计算 `protectedBy`、stability、claims；
- 播放 Restore 动效；
- UI 从 Overload 状态切回 Normal。

---

# 9. 重要限制：恢复当回合不得立即继续成长

这是 v0.6.1 必须新增的明确时序。

恢复 Overload 的据点，在同一次 `beginTurn` 中：

- 只完成“恢复”；
- **不执行成长**；
- 不因为 stage < 2 而立刻从 1×1→3×3 或 3×3→5×5；
- 不因为 5×5 内存在失地而在恢复瞬间继续扩回去。

应给该塔设置等价于：

```text
skipGrowthThisTurn = currentTurnIndex
```

或复用一个清晰的 activation / cooldown 标识。

下一次该 owner 的正常回合开始，才重新获得成长资格。

---

# 10. Take Over 完成当回合同样不得追加成长

保持 v0.6.0 已有设计，并在 v0.6.1 继续明确：

Take Over 完成时：

1. 保留目标塔 stage；
2. 进行接管完成所要求的合法范围激活 / 染色；
3. 创建对应 Pending；
4. 切换 tower owner；
5. 初始化 / 更新其当前 `influenceCells`；
6. **本次 beginTurn 不再调用该塔正常成长**。

下一次接管方自己的正常成长阶段才允许继续成长 / 恢复失地。

---

# 11. 后续正常成长：逐步恢复到 5×5

## 11.1 总原则

每座 Normal 据点都应持续拥有“最终趋向完整 5×5”的能力。

但：

- 不可穿透敌方有效 Protected；
- 不可在恢复 / 接管完成同一次结算里额外成长；
- 失去的 Stable 敌方领土不会在 Restore 瞬间被强制清除。

## 11.2 stage < 2

延续现有结构成长：

- 1×1 → 3×3；
- 3×3 → 5×5。

每次只提升一级。

成长时：

- 检查新 stage 允许的完整范围；
- 对不被敌方 Protected 的可成长格执行己方染色；
- 将成功控制的格加入 `influenceCells`；
- 被敌方 Protected 的格跳过，但不永久降低 stage。

因此可能出现：

> stage 已经为 2，但实际 `influenceCells` 不是完整 25 格。

这是合法状态。

## 11.3 stage == 2 且存在失地

成熟据点仍应在之后的己方成长阶段尝试把可恢复区域逐步重新纳入。

推荐算法：

1. 在 5×5 理论范围内找到 `influenceCells` 之外的候选格；
2. 排除敌方 Protected / Locked 格；
3. 只选择与当前 `influenceCells` **上下左右相邻**的候选格作为本轮 frontier；
4. 本轮一次性加入这一层 frontier；
5. 将这些格染成 tower.owner；
6. 下一己方回合再继续下一层。

这样可以自然实现：

- 只丢一列 → 下一次成长可恢复相邻的一列；
- 丢两层 → 分两次向外恢复；
- 敌方锁定挡住 → 绕不过保护，不允许“跳格恢复”；
- 敌方保护取消后 → 重新进入 frontier 候选。

不要一次性把所有 5×5 未保护格全部抢回，否则会破坏“逐步恢复”的战术窗口。

# 12. `beginTurn` 推荐结算顺序

在尽量保留 v0.6.0 当前顺序的前提下，v0.6.1 推荐：

```text
1. turnIndex +1 / 玩家 turns +1
2. recompute
3. resolveDueTakeovers(current)
4. recompute
5. resolveDuePendingClaims(current)
6. recompute
7. recoverExpiredOverloads(current)
8. recompute + reconcile influenceCells
9. growEligibleTowers(current)
   - 排除本回合刚恢复的塔
   - 排除本回合刚完成 Take Over 的塔
10. recompute
11. reconcile overloaded residual influence
12. reset relay/action/move flags
13. phase = IDLE
14. 播放视觉表现后开放输入
```

开发时可以用等价顺序，但必须满足以下不可违反条件：

- Take Over 完成先于正常成长；
- Pending 转换保持现有规则；
- Restore 当回合不成长；
- Take Over 完成当回合不成长；
- Enemy tower grow 的结果能够缩减对方 Overload residual influence；
- UI 必须读取最终规则结果，而不是独立模拟。

---

# 13. `influenceCells` 同步与清理

建议新增一个明确函数，例如：

```text
reconcileTowerInfluence(state)
```

职责：

## 13.1 对 Overloaded tower

遍历其 `influenceCells`：

- 如果该格已成为 enemy Stable → 删除；
- 如果该格被 enemy Protected → 删除；
- enemy Temporary 可保留；
- friendly / own color 可保留。

## 13.2 对 Normal tower

- `influenceCells` 不应包含理论 stage 范围外格子；
- Protected 只从其 own-color influence 格产生；
- 成长成功后把新格加入；
- 重部署移除旧 tower 时同时删除旧 tower influence 数据。

## 13.3 对 Contested tower

- 保留必要的数据供接管 / 收复使用；
- Contested 期间不产生 Protected；
- Contested 期间不自动成长；
- UI 仍可显示其争夺影响范围。

---

# 14. 边界情况

必须显式处理。

## 14.1 多友塔重叠

如果 Overload 塔某个原格仍由另一座正常友塔保护：

- 该格仍受友方整体 Protected；
- 不允许敌方正常染色；
- 不因为单塔 Overload 就错误失去阵营保护。

这与现有 `protectedBy` 多来源逻辑一致。

## 14.2 Overload 塔中心

塔实体继续存在。

- 敌方不能因为普通染色让塔“消失”；
- Take Over 仍按 v0.6.0 的合法位置和成熟条件判断；
- UI 必须始终能找到塔和其 residual range。

## 14.3 地图边缘据点

5×5 理论范围裁剪到地图内部。

- 不生成越界格；
- UI 边界按真实地图内格集合绘制。

## 14.4 irregular influence

一侧被敌塔锁住后，`influenceCells` 可以呈 L 形、缺口形、不完整矩形。

- UI 必须按真实格集合画轮廓；
- 不得仍画一个完整 5×5 假框。

## 14.5 失去保护后又重新变 Temporary

如果某格已经因为变成 enemy Stable 而从 residual influence 删除：

- 即使之后敌方 Stable 又断联变成 Temporary；
- 也不会自动回到旧 residual influence；
- 需要未来通过正常 growth frontier 重新夺回。

这是“已经失去影响力”的持久含义。

# 15. UI 总方向：A · Flux 精修

采用已经确认的 A 风格。

核心视觉关键词：

# 16. 三种基础格子：全部取消常驻动画

这是已确认要求。

## 16.1 Stable

- 使用纯色；
- 不用 gradient；
- 不用扫描；
- 不用呼吸；
- 不用颗粒运动；
- 格子之间继续保留非常细的结构缝隙。

Stable 的任务是提供“视觉安静区域”。

## 16.2 Protected

不再使用 v0.6.0 的：

- 四角完整锁定符号；
- 中心光膜；
- 共享低频保护扫描。

改成静态简化设计。

推荐：

- 格子保持原 Stable 阵营色；
- 在格子内部 inset 约 12%–18%；
- 绘制一条约 1px 的阵营色内部细框；
- 可以是完整细框，也可以做非常小的开口，但不要回到四个巨大角括号；
- 透明度约 45%–65%；
- 发光仅允许非常轻微，不能形成常驻闪烁；
- 无动画。

目标：

> 玩家一眼知道“这是锁定 / 保护格”，但大片保护区不会变成满屏动画。

## 16.3 Unstable

必须完全取消：

- 漂移 gradient；
- 渐变阴影；
- 动态扫描；
- 呼吸；
- 移动纹理。

新版设计：

1. 保留阵营原 hue；
2. 整格比 Stable 统一压暗约 15%–22%；
3. 使用 near-black，例如 `#05080b` / `#071018`；
4. 在内部画“手绘感 / 线稿感”的阴影标记；
5. 推荐使用：
   - 一条短 L 形内角线；
   - 或两个对角短线；
   - 或不完整的内侧暗线；
6. 线宽约 1–1.5px；
7. opacity 约 50%–75%；
8. 无 gradient；
9. 无动画。

它应看起来像：

> 同一块阵营地板被“压暗并画上黑色断联阴影线”。

而不是一块在流动的黑雾。

# 25. 保留并精修的现有瞬时动效

以下现有反馈继续存在。

## 25.1 Bounce

- 每一次真实碰撞都播放；
- 3 个左右短火花；
- 多次连续真实碰撞可以分别出现；
- 不因为“防止重叠”而吞掉真实物理事件。

## 25.2 Capture

- 快速向中心收缩的捕获环；
- 约 130–160ms；
- 清晰但短。

## 25.3 Charge

保持 I / II / III 逐级增强：

- I：少量粒子向中心收束；
- II：更多粒子、两层；
- III：最明显，但仍受全局粒子预算限制。

不把 Charge 粒子改成常驻。

## 25.4 Fire / Launch / Land

- 起点 / 落点短扩散环；
- 保持轻量。

## 25.5 Missile Trail

- 保持短尾迹；
- Charge 越高可稍长；
- 不使用长时间持续烟雾。

## 25.6 Blast

- 中心短闪；
- 扩散环；
- Charge 高级范围更大；
- 不叠加不必要全屏 flash。

## 25.7 Crosscut

- 四方向扫光；
- 到 Protected 格立即停止；
- 命中 Protected 时该格只做一次短抗性闪光；
- 不让整个 Protected 区常驻发光。

## 25.8 Damage

继续：

- 独立真实伤害都反馈；
- 短受击环；
- `−1 HP`；
- 20ms Hit Stop；
- 连续真实多段伤害允许分别播放。

## 25.9 Heal

继续：

- 绿色 `+1 HP`；
- 角色短高亮；
- 不新增恢复音效；
- 不新增额外 shake。

## 25.10 Build

- 轮廓 / 四角向内收束；
- 核心落定；
- 约 260ms。

## 25.11 Redeploy

- 原点收束；
- 新点建立；
- 保持一次主反馈。

## 25.12 Grow

推荐在现版扩张环基础上升级：

1. 即将新增的 frontier 先出现一圈薄范围线，约 80–120ms；
2. 对应格子随后统一浮起 / 落定；
3. 整轮成长只播放一组主音效；
4. 不给每格独立 shake / sound。

## 25.13 Destroy

- 保持碎裂向下散落；
- 普通强度。

## 25.14 Siege

- 更强碎裂；
- 更明显冲击环；
- 40ms Hit Stop；
- 主 shake；
- 和普通 Destroy 必须能明显区分。

# 30. 性能要求

当前游戏是 18×32 手机战场，基础格数量很大。

## 30.1 禁止

- 每个 Stable / Protected / Unstable 格各自运行 animation timer；
- 每格独立 requestAnimationFrame；
- 大量 CSS DOM 覆盖 Canvas；
- 每格持续 shadowBlur；
- 每格持续 gradient 动画；
- 无限制 particle。

## 30.2 推荐

继续 Canvas 单次 render pass。

持续状态用：

```text
global time → 计算 arc angle / dash offset
```

而不是独立 timer。

维持现有粒子预算思想：

- 正常模式总瞬时 particle primitive 维持有限预算；
- Reduce Motion 大幅下降；
- 据点旋转环不使用粒子预算。

如果性能不足，削减顺序：

1. 先降低非核心 glow；
2. 再减少粒子；
3. 再关闭次级 ring；
4. 不得先删除规则状态边线和关键状态提示。

# 34. 必须新增的自动化规则测试

## Overload

1. 5×5 Normal tower → Overload，保留 stage 和 influence。

8. enemy Protected 格 Restore 不回色。

12. Take Over Complete 同一 beginTurn 不 Growth。

14. stage 0→1 一次一级。

# 36. UI 验收条件

## 基础格

- Stable 没有任何常驻 animation。
- Protected 没有任何常驻 animation。
- Unstable 没有任何常驻 animation。
- Unstable 没有 gradient。
- 三类格在手机上无需放大即可识别。
- Unstable 明显比 Stable 暗，但仍能清楚辨认阵营色。
- Protected 内线不会让大量保护区显得像密集网格噪音。

## 据点

- Relay available 一眼可识别。
- Relay used 明显比 available 弱。
- Overload 既能找到 tower，也能找到 residual range。
- Contested 明显表现红蓝双方争夺。
- 所有文字无边框。
- 动画速度足够慢，不产生“风扇”感。

## 区域

- Overload range 被 enemy 吃掉后边界真实缩小。
- Contested tower range 和 contested territory 使用同一视觉语言。
- 大面积区域边界不会遮挡 tile 信息。

# 38. 禁止的实现方式

以下应视为错误实现：

- Overload 恢复直接把整个 stage 方形全部改回己色；
- enemy Stable 格在 Restore 瞬间被抢回；
- enemy Protected 格被 Growth 覆盖；
- Restore 完成马上又 Grow；
- Take Over Complete 马上又 Grow；
- 用固定 5×5 虚线假装 residual range；
- Overload influence UI 不随着 enemy growth 缩小；
- Protected / Unstable 每个格常驻播放动画；
- Unstable 使用方向性渐变阴影；
- 为所有格添加大量 glow / particle；
- “争夺中 / 过载”使用大 pill / 大边框遮住战场；
- 为每格建立独立 timer；
- 视觉层自行推导规则状态，与 engine 不一致。

# 41. 开发者最终判断原则

如果实现过程中出现本规格没有逐字覆盖的边界问题，按以下优先级做决定：

1. **规则权威状态必须来自 engine。**
2. **据点最终目标是逐步趋向 5×5，而不是瞬间强制拥有 5×5。**
3. **敌方真正 Stable / Protected 的成果必须得到尊重。**
4. **Temporary 表示尚未真正锁定，Restore 可夺回原 residual influence。**
5. **恢复与接管完成都只完成自身结算，不顺带获得一次额外成长。**
6. **UI 必须帮助玩家理解规则，而不是创造新的隐藏状态。**
7. **基础区域保持安静，把动态资源留给真正重要的战术事件。**
8. **科技感来自线条、节奏、空间和信息层级，而不是大量 glow、gradient 和粒子。**
9. **任何美术优化都不得降低手机端一眼判断格子状态的能力。**
10. **遇到多个可行视觉方案时，选择更简洁、更稳定、更容易在 Canvas 中一致实现的方案。**
