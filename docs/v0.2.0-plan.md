# Territory Network Implementation Plan

Goal: implement the approved 弹射领地战争_v0.2.0_开发规格.docx as v0.2.0-territory-network and publish the existing Sites project plus GitHub main.

Architecture: keep Vite and ES modules. Engine owns discrete territory/tower/turn state, physics owns continuous movement and collision, renderer reads state, main binds floating controls. Logical profile is locked at match creation.

Execution: native implementation; user has explicitly requested development and publication against the completed specification.

## Tasks
- [x] Rules and regression tests: four-neighbor connectivity; snapshot claims with rescue; five towers and growth; independent move/action tokens; final-round scoring.
- [x] Shared physics and tests: role slingshot, independent role relays, once-per-turn missile relays, three charges, immediate collision HP, swept carried color entries, deterministic legal release, siege order.
- [x] Fullscreen UI and tests: aspect-fit camera, locked profiles, touch rotation, floating HUD, action stack, map tower selection, aim cancellation, handoff, result and rematch.
- [ ] Release: run full test/check/build suite; update README/CHANGELOG; synchronize verified source to GitHub main and Sites.

## Review focus
- HP zero aborts every remaining simulation operation.
- Same-cell friendly role/tower cannot shield role from enemy missile.
- Release searches backward along incoming path; hostile role/tower never overlap.
- Orientation changes preserve world and pending/relay/token state.
- Cancel after a committed relay finishes that one movement/shot, never refunds its token.

Constraints: local PvP only; HP 10; max towers 5 including initial stage-2 tower; one missile/action; 10/14/18 rounds; 80% only at full round end; no respawn, shield, melee, queen movement, undo, multiplayer or persistence.
